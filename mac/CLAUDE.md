# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**ScreenTune** is a macOS menubar app for display color calibration: per-screen tone curves (black / mid / white per RGB channel), warmth (color temperature), gamma, contrast, and system-wide saturation, with a master on/off switch and hold-to-compare. GitHub: `Bo0ii/ScreenTune`.

## Build and test

Open `ScreenTune.xcodeproj` in Xcode, or build from the CLI:

```bash
xcodebuild -project ScreenTune.xcodeproj -scheme ScreenTune -configuration Debug build
```

Logic checks (no Xcode test target; compiles the AppKit-free files with `swiftc` and runs them):

```bash
Tests/run.sh
```

Only `DisplaySettings.swift` and `SettingsStore.swift` are covered. Keep them free of AppKit/CoreGraphics so the script can compile them. Anything visual (overlays, gamma tables, UI) has to be checked by running the app.

- **Deployment target**: macOS 26.0 (Liquid Glass APIs are used without availability checks)
- **Language**: Swift 5 mode, SwiftUI + AppKit
- **Bundle ID**: `com.example.ScreenTune`. Change before any release. `UserDefaults` is keyed by bundle ID, so changing it drops every saved setting.
- **Info.plist**: generated from build settings. `LSUIElement = YES` hides the Dock icon.
- The `ScreenTune` scheme is auto-generated by Xcode (no shared scheme file is committed).
- **App icon**: `ScreenTune/AppIcon.icon` is an Icon Composer (Liquid Glass) document: `icon.json` plus SVG layers in `Assets/` (screen gradient, stand, slider track, knob), with a dark-appearance fill. Edit it in Icon Composer (inside Xcode.app) or by hand, and preview without building:
  ```bash
  "/Applications/Xcode.app/Contents/Applications/Icon Composer.app/Contents/Executables/ictool" ScreenTune/AppIcon.icon \
      --export-image --output-file /tmp/icon.png --platform macOS --rendition Default --width 512 --height 512 --scale 2
  ```
  (`xcrun ictool` is a different tool and rejects these arguments.) `Assets.xcassets` no longer contains an app icon set.

## Architecture

Menubar-only app. `AppDelegate` creates one `CalibrationModel` and a `StatusBarController`; the model is passed to every view. The SwiftUI `App` only has an empty `Settings` scene because the panel is AppKit.

### Per-screen settings

`CalibrationModel.settings` is `[displayUUID: DisplaySettings]`. Screens are identified by `CGDisplayCreateUUIDFromDisplayID`, which is stable across reconnects and reboots (a `CGDirectDisplayID` is not). `screens` lists the connected displays (`NSScreen.screens`, names from `localizedName`, duplicates numbered). `selectedScreenID` is the screen the popover edits; `current` is a get/set view of that screen's settings, and all sliders bind through it. Disconnected screens keep their stored settings.

### Apply pipeline

Every change to `settings` diffs old vs new per screen and marks it tone-dirty and/or saturation-dirty, then `scheduleFlush()` runs one `flush()` on the next main-queue pass. That coalesces bursts (reset, import) into a single display write and a single `UserDefaults` write, while slider drags still apply live on every tick. Tone and saturation are applied independently, so dragging saturation never rewrites gamma tables and vice versa.

### Tone / gamma / contrast (`GammaController`)

`DisplaySettings.transferTable()` builds a 256-entry table per channel: linearize (`pow(t, 2.2)`) -> contrast around 0.5 -> tone (black lift, mid power, white scale times warmth) -> re-encode (`pow(v, 1/gamma)`) -> clamp.

Warmth is `temperature` in Kelvin (3000...6500, 6500 = neutral). `warmthMultipliers(kelvin:)` uses Tanner Helland's blackbody approximation, normalizes it so 6500K is exactly (1, 1, 1), and converts to linear light (`pow(x, 2.2)`) because it multiplies inside the linear part of the pipeline. At 3000K white becomes roughly (1.0, 0.70, 0.44). The popover slider is mirrored (left = neutral, right = warm) like Night Shift. `GammaController.apply` writes it with `CGSetDisplayTransferByTable` for that display only and caches it for drift checks.

Screens whose tone is at defaults (`isToneIdentity`) are **never written**, so Night Shift, True Tone and the display's ColorSync calibration keep working there. When a screen goes back to defaults, `CGDisplayRestoreColorSyncSettings()` restores all displays (there is no per-display restore) and the tables still in use are written again.

### Saturation (`SaturationOverlay`)

Gamma tables are per channel and cannot mix channels, so saturation needs a compositor-level filter. Public API cannot do it: `CALayer.backgroundFilters` only sees this app's own layers, so on a transparent overlay window it filters nothing (this was the "saturation slider does nothing" bug).

The working approach, verified on macOS 27: each screen with saturation away from 1.0 gets a borderless, click-through window at `.screenSaver` level holding a private `CABackdropLayer` with `windowServerAware = true` and a private `CAFilter` of type `colorSaturate` (`inputAmount` 0 = gray, 1 = unchanged, 2 = boosted). The WindowServer fills the backdrop with everything behind the window and filters it on the GPU. No screen-recording permission is needed. A `CIFilter` (e.g. `CIColorControls`) on the backdrop does **not** work because the WindowServer cannot run Core Image filters.

The filter is named `saturate`, and slider changes update it in place via `filters.saturate.inputAmount` inside a disabled-actions `CATransaction`, with no new windows or layers per tick. The overlay is removed when saturation is within `DisplaySettings.saturationThreshold` (0.004) of 1.0. If the private classes are missing, `SaturationOverlay.isSupported` is false and the UI disables the slider. Overlays are rebuilt from scratch on any screen configuration change. The window is created without the `screen:` initializer argument on purpose: with it, `contentRect` becomes relative to that screen and secondary screens end up offset.

### On/off and compare

`isEnabled` (persisted as `enabled`, default on) is the master switch; `isComparing` is true only while the eye button is held. When either makes the model inactive, `effectiveSettings(for:)` returns defaults for every screen and `activeStateChanged()` does one `GammaController.removeAll()` (a single ColorSync restore) plus `SaturationOverlay.removeAll()`, so compare is instant. Settings are kept and re-applied when active again. The menu bar icon uses `appearsDisabled` while off.

### Preview patterns

The popover's gray ramp and swatches are drawn **unprocessed**. The screen's own correction already applies to them; pre-correcting them in software (as older versions did) applied the correction twice.

### Drift correction

macOS resets gamma tables after Night Shift, True Tone, screen saver and wake. Recovery paths (all only touch screens with a written table):

1. **2-second timer** (0.5 s tolerance, common run loop mode): re-writes any table that drifted by more than 0.02. Skipped while the user is away (no input for 10 s) so it does not fight a KVM switch, and skipped entirely when no tables are applied.
2. **User return**: global and local `NSEvent` monitors (mouse move, clicks, drags, scroll) track activity. The first event after 10 s of absence re-writes drifted tables. The local monitor covers events sent to ScreenTune itself (global monitors never see those).
3. **Notifications**: `didChangeScreenParametersNotification` rebuilds the screen list, overlays and tables; `screensDidWake` / `didWake` re-write all tables. All debounced 500 ms.

### DeskRiv KVM integration

ScreenTune listens for the Darwin notifications `com.deskriv.displayDimmed` and `com.deskriv.displayRestored` via `CFNotificationCenterGetDarwinNotifyCenter()` (wrapped by the private `_DarwinObserver` class). DeskRiv is the user's own KVM app (separate repo).

- `displayDimmed` sets `deskrivIsDimming = true`. DeskRiv owns the gamma tables until restored.
- `displayRestored` clears the flag and re-applies every screen's tone.

Every gamma write path (flush, timer, user return, wake) checks `deskrivIsDimming`. Changes made while dimmed are saved and written on restore. Saturation overlays are unaffected by DeskRiv.

### Persistence (`SettingsStore`)

All per-screen settings are one JSON blob under `displaySettings.v2`; the popover's selected screen is under `selectedScreen`. Everything loaded is passed through `DisplaySettings.clamped()` (slider ranges, non-finite values fall back to defaults), because an out-of-range gamma or mid value can make a screen unreadable.

Versions before per-screen settings stored one flat key per value (`blackRed`, `gamma`, ...) for the main display. On first launch with an empty v2 store, those are migrated to the main display's UUID and saved. The old keys are **kept**, so an older build with the same bundle ID still has its settings.

### Profiles

Export and import use `DisplaySettings` JSON (same 12 keys as the original `CalibrationProfile`, so old files still import; missing keys fall back to defaults). They apply to the selected screen. Imports are clamped. Default export name: `ScreenTune - <screen name>.json`.

### UI

- Panel: `MenuBarExtra` was replaced because its window background can't be controlled. `StatusBarController` owns an `NSStatusItem` (opens on mouse down) and `MenuPanel`, a borderless non-activating `NSPanel` at `.popUpMenu` level whose content view is an `NSVisualEffectView` (`.popover` material, behind-window blending) rounded with a `maskImage` so blur and shadow follow the corners. It opens centered under the icon with a 0.12 s fade and closes on outside click (global monitor), losing key status, Esc (`cancelOperation`), or clicking the icon again (a 0.2 s guard stops the resign-then-toggle race from reopening it).
- Content: header with title, hold-to-compare eye button and on/off switch (like the Wi-Fi menu); a "Screen" list of menu rows with a checkmark (only with 2+ screens); Tone / Adjust / Preview cards with a subtle `.fill.quaternary` background and no borders, dimmed and disabled while off; then menu rows (Reset / Settings… ⌘, / Quit ScreenTune ⌘Q). `MenuRow` has hover, pressed and disabled states. No glass buttons on the frosted background: glass-on-blur looked off. System controls (switch, segmented control, sliders) still pick up Liquid Glass automatically.
- Settings: `SettingsWindowManager.shared` reuses one `NSWindow` (`NSHostingController`, frame autosave name `ScreenTuneSettings`) hosting a `.grouped` `Form`. Launch at Login uses `SMAppService.mainApp`, keeps its status in `@State` so the toggle refreshes, shows errors, and links to Login Items when approval is required.
